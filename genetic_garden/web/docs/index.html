How it works

Seven algorithms, each one page. They are meant to be read in order, but every page stands on its own. Each figure is generated by the code it describes, so the pictures cannot drift away from the implementation.

Genomes

A project id becomes a plant, and the same plant every time. Everything downstream is a pure function of this.

Growth

Contributions become a maturity profile. One number drives everything, and it is never allowed to rearrange the plant.

The skeleton

Branch geometry and organ placement: three growth rules, a walk with forces on it, and a draw order that does more work than it looks like it should.

Organs

Every blade in the system is one function with different constants. Blooms are the exception, and are sampled from a set of archetypes instead.

Colour

Built in HSL from a few genome-driven anchors, so a plant's parts always harmonise — with one relationship that cannot be left to taste.

Rendering

Turning a skeleton into SVG, at a size it will actually be seen at. Most of this module is about what not to draw.

The garden scene

Many plants strewn over a plane at random ages. Three ideas carry it and there is not much else.

The pipeline

Five stages, each a module, each ignorant of the next. A garden scene composes many finished plants on top.

genome.py    id --hash--> genes --> traits
growth.py    contributions --> maturity profile
skeleton.py  genome + growth --> branches + organ sites
organs.py    leaves, petals, blooms as path geometry
render.py    skeleton + palette --> SVG
garden.py    many plants --> one scene
